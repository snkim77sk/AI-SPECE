# Site v5.2.17: collection health visibility

The header previously displayed the newest successful Site import across all
sources. Active delivery imports could therefore hide failed budget collection.
This update separates imported data from the Windows collector's reported state.

## Changes

- Show G2B and LOFIN collection state separately from Site import time and rows.
- Preserve failures, held scopes, configured quota waits, and unknown outcomes.
- Stop showing current healthy, running, or quota-remaining states after a failed
  status read, after five minutes without a fresh report, or across a KST day change.
- Keep the last observation as history and label its time explicitly.
- Refresh the program-link view every 60 seconds and on return to the tab.
- Clarify that imported source rows are cumulative page rows, not unique current
  lighting products or proof that nationwide collection is complete.
- Treat Windows Running result 267009 as a running observation, not an exit failure.

## Compatibility

This is a Site display update. The existing server-sync response version 5.2.16,
Windows status versions 5.2.8/5.2.9, import protocol, database schema, page receipts,
and access policy remain compatible with the installed Windows clients.

The existing payload does not contain a historical last-success timestamp. The
view reports only supplied run timestamps and verified page counts; it does not
invent an earlier successful collection date.

## Validation

Targeted regression cases cover mixed source success/failure, failed transport,
stale and previous-day observations, task Running results, configured quota
waits, held scopes, and zero/missing counts. The targeted 26 tests passed before
the full publication checks. An independent read-only review confirmed these
boundaries. The full regression suite passed all 740 cases. TypeScript checking
also passed after explicit response-object narrowing in the header fetch path.

## Windows repairs still pending

The requested Windows budget timeout repair, recent-day revalidation, overlap
recovery, and unattended-logon configuration were not applied. Desktop Commander
reported its monthly usage limit on the first new server-access call. No Windows
files, tasks, source data, or collector processes were changed in this update.

The previous audit found repeated 85-second budget timeouts before new calls and
recent empty days marked COMPLETE without later revalidation. Recent-day or
overlap recovery must preserve original receipts and allocate a new generation:
the Site page identity contains dataset, scope, generation, and page number.
Reusing an existing page identity with changed contents is rejected.
