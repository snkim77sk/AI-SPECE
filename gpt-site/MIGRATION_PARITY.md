## v29 dashboard aggregate cache

Repeated dashboard reads use a 60-second optional D1 cache of aggregate values only. Cache identity includes mode, the resolved query window, and all four source epochs (delivery, budgets, revision history, daily observations). A cache hit requires strict payload validation and matching epochs before returning. Cold computation verifies the epochs before storage, the INSERT itself checks all four epochs atomically, and the response checks them again. Cache failures do not hide required source-read failures. Readiness, keys-present flags, quota configuration, and request-time metadata remain uncached.

Payloads are capped at 512 KiB and the existing shared query cache is pruned to 64 entries per mode. This is a bounded per-response cache, not an attempt to change the fixed platform memory allowance. An explicit aggregateCache hit field supports hosted measurement. Warm requests make three database reads with no aggregate scans, versus six aggregate scans on a miss.
