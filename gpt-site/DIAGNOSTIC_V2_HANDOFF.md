## Bounds and limitations

Fetch plus body read has a 25-second timeout capped by the remaining 90-second total deadline. Database promises are also bounded by that deadline. Cancellation cannot revoke already submitted database work; late/uncertain reservation or audit writes are never replayed. JavaScript synchronous parsing cannot be preempted mid-instruction; the existing 8 MiB response cap and post-processing deadline checks bound input and reject an over-deadline result. Hosted platform CPU/memory and actual egress are not validated by local tests.

Diagnostics never persist/log exception text, cause, stack, headers, redirect locations, URLs/query values, raw payloads or rows. Only exact safe error name/code categories, observed timeout flag, HTTP status, elapsed time, phase and optional counts/size/hash are emitted. A TypeError becomes SOURCE_FETCH_FAILED, not a claim of DNS/firewall failure. Old route semantics are unchanged. Read-only source validation may prepare a commit plan but has no collection/source write execution path.
