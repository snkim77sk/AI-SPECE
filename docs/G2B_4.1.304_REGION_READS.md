# G2B 4.1.304 regional budget read correction

Development branch only. The starting main was `1a53e459808e1c4d43f05fb6a0dec043e54e4c41` / `4.1.303`. This task does not merge main or deploy Cafe24.

## Problem and scope

A 2026 budget query with all other filters cleared returned zero projects, zero money and no institutions for 충남/충북. Nationwide keyword results prove that matching text exists but are not exact regional totals, because keyword search spans several fields.

The read layer generated formal prefixes such as 충청남도/충청남 and omitted 충남. SQL discarded stored alias rows before Python could normalize them. Institution alias handling covered only 서울/경기, and the institution selector read only DETAIL_EXECUTION.

## Changed behavior

- Common geography rules resolve formal names, existing short aliases, historical names and recognized compact institution prefixes. Ambiguous 광주시/광주시청 and arbitrary institution names do not establish a metropolitan region.
- Region is the first recognized value in region_name, org_name, institution_name. SQL options, bounded lists, full COUNT/SUM and revisions use the same rule as Python.
- Every stored budget layer contributes institution choices. Alias-equivalent city and top-level government choices select all matching stored spellings. No new municipal or uncollected-institution registry is guessed.
- History institution and department predicates run before its bounded SQL LIMIT. Existing category/history limits remain bounded.
- Raw RUNNING checkpoints remain intact after a bounded PARTIAL batch. Display state distinguishes verified active work, partial completion/retry waits and old checkpoint freshness consistently in cards, recent activity and partition views. A stale checkpoint is not proof that all collection has stopped.
